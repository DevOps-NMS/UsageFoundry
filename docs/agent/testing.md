The ten modules at the end of that list are the ones whose grounds are not obvious from the function's name, and each states them in its own file's docblock.
`budgetFromForm` is where every limit's off state is decided: `null` is the wire form of "off", so a number left in a box the operator switched off is a perfectly valid `BudgetPolicy` and starts an unattended agent under a cap nobody set, and the window pair reads 0–100 on the form against 0–1 on the wire, which makes a slip of a hundred a guard that never fires.
`authBootSignal` is whether anything at all is said about an install that serves every route to whoever can reach the port.
`config.ts`'s three each fail *as an ordinary state* rather than as an error — a fifth workspace slot compose never mounted looks exactly like a mounted directory with nothing in it, and the wrong GitHub token **works**, leaving a commit in somebody else's history as the only evidence.
`configCheck`'s two decide which configurations boot and which are refused, which is the one decision made before anything else can report.
`git.ts`'s are what every git call this app makes carries: a missing `-c` is a repository-controlled hook run by this server's own git child, with no permission mode and no line in `run_events`, and a variable that survives the scrub is that hook handed `DATA_DIR`.
`jsonNoStore` serves the one page with nothing but a poll to learn from, so a cached body is the last thing it ever sees — frozen at `thinking`, with the composer disabled; the same file reads source text for the wiring half, which no other test here does, because a header on the wire has no pure function behind it.
`loginLimiter`'s two fail in opposite directions, one that never fires being bit-for-bit the unbounded route and one that never lets go locking the operator out of an app whose only other credential is an environment variable and a restart.
`plugins.ts`'s two decide what code every agent loads, and a bare `--plugin-dir` with no value takes the *next* argv entry as its path — which in `buildArgs` is a permission mode nobody chose.
`retention.ts`'s pure half decides what lands on disk and what is discarded from it, `releasableRuns`' grounds exactly.
`sessionToken`'s four are the whole of what keeps a captured cookie from being the master credential.
Three of them are not pure functions, and each earns the exception on its own terms.
`settleOnExit` spawns a real child, which is what the fault requires: an inherited pipe held open past the exit is the entire mechanism, and a stubbed emitter would only pin the wiring back to whatever it was written against.
`sendChatMessage`'s claim on a chat is the second, driven against a temporary database with `spawn` replaced by a counter — what it decides is not a value but whether a second billed child joins a conversation that already has one, and the only assertion that says so is the number of children.
`jsonRequest` is the third, and it is the one that makes the request: what it pins is that it *returns*, whatever happens, because an unguarded `fetch` rejecting out of a handler reports nothing at all — the chat page's flag disabling the composer, Approve, Reject and Select-all stayed set with no way back but a reload; the branches page's Land, Purge and Delete re-enabled their button and left the table exactly as it was, which is what a press that did nothing also looks like; and the land card's poll went on rendering a conflict resolution as in flight long after it had finished.
The status it carries is the other half — `null` is nobody answered and a number is somebody refused, which is the split between `pollFailureMessage` on a poll and `actionFailureMessage` beside a press that may or may not have landed.
`chatRequest` is a caller of it and keeps its own test, because the chat page reads a thread off the answer and that shape is its own.
Eight are renderings rather than functions — every `*.test.tsx` in the tree, which is the whole of that class and is countable as `find src -name '*.test.tsx' | wc -l`.
Four of them are `Meter.test.tsx`, `LiveTelemetry.test.tsx`, `Markdown.test.tsx` and `ui/Table.test.tsx`, and they clear the same bar by the same argument: what they pin is *something the reader would act on*, wrong in a way that throws nothing and typechecks (a solid green bar that means "we don't know"; a first-party figure that reads as an addend to the transcript-derived meter beside it; a report that ends in silence because the cycle was killed with a code fence still open).
The fourth is `Meter`'s argument at a second breakpoint-shaped invariant, and it fails in two directions rather than one.
`Markdown.test.tsx`'s wikilink cases are the same bar reached from the knowledge page: a `[[link]]` the renderer does not recognise falls through as ordinary prose, and a vault with 183 dangling links then reads as a vault with none — on the page whose reason for existing is to find them.
So both signs are pinned, a resolved link *and* an unresolved one, along with the third answer that is neither: a target that exists and is not a note, which marked broken would report a healthy vault as a broken one.
The parsing cases sit beside them because each way of misreading a link is silent — a `|label` swallowed into the target breaks a link that resolves, an alias read as a heading points at a note that exists — and two cases pin what must *not* become a link, since the vault's own notes quote wikilinks inside code spans and fences while writing about them.
The last pair is the emphasis rescan: a bolded wikilink reached `<strong>` as literal text until the inner text was scanned again, and the second half pins that a caller with no vault behind it renders byte-for-byte what it did before, because every caller that predates the resolver prop is a model's report rather than a note.
The Obsidian block below them is one argument repeated per construct, and the argument is the measurement in `docs/verification.md`: 760 of the real vault's 785 notes carry a callout, 621 a table and 524 a task list, and a construct this renderer does not know does not error — it arrives on the page as the punctuation the author typed, which is what "the notes are not rendered" turned out to mean.
So each case pins the marker being *consumed* rather than the box being pretty: a callout that stays `[!warning]`, a table that stays a row of pipes, a checklist that stays `[ ]`.
Three of them go further than that because the failure is a wrong reading rather than an unrendered one — a callout's tone is its meaning and a danger drawn in the note colour is a warning the reader does not get; a `- [x]` drawn unchecked inverts what the note says; and a table's stacked `label` is a second copy of the head, so handing it the raw string put markdown on the phone in a table that read correctly on the desktop, which is a bug no desktop screenshot can contain.
Two more are the same shape as the wikilink pair, gating on the resolver: a `#tag` is a chip in a note and a word in a report, and a footnote reference with no definition behind it stays literal for the reason a dangling wikilink is marked rather than linked.
A third gate has a test of its own because it is the only invariant here that a *caller* can break from outside: a nested disclosure is on this app's never-used list, `RunOutput` renders every earlier cycle's report inside a `Disclosure`, and a model writing Obsidian's `> [!note]-` into a report would therefore build one from the inside — so folding is refused without a vault and refused again inside a callout's own body, and the case pins both rungs along with the fact that a refusal renders the text *open* rather than dropping it.
The three parser cases that are not about a construct at all — a pipe that is not a table, an escaped marker, an underscore inside a word — are there because each one *adds* meaning to text that had none, and a heading silently turned into a one-column grid or an identifier turned into italics is content this changed rather than content it failed to draw.
`Table`'s `stack` takes the column heads off the screen below `md` and makes the grid one block per record, so the only thing naming a value there is the `label` its own `Td` carries and the only thing carrying the row and column relationships is the explicit ARIA role — `display: block` strips the implicit one in every engine.
Drop either and the desktop is pixel-identical and the phone is a column of unnamed figures, or a stack of anonymous boxes to a screen reader.
The other direction is the promise the change was made under: a table that did not ask to stack must emit exactly what it emitted before, and since every mobile rule here is behind a breakpoint prefix, "no `md:` anywhere in a flat table" is the whole of that claim in one assertion — which is also the only form of it that can be checked without a browser.
The wrapper around a labelled value is pinned for the same reason from the other side: it is `md:contents` so it generates no box in the flat table, and a plain `block` there would be a silent desktop change in every one of the twenty-two tables that now stack.
Its last case is why `stack` is a *context* rather than a prop, and it is the one thing the widened coverage rests on: the workflow instance page draws two tables out of one `RunTableHead` and one `RunRows`, so a shared body that had to be told would be told at one call site and forgotten at the other — and the table that was not told would render its figures unnamed below the breakpoint, on a page whose desktop is unchanged either way.
Its control is half of it, for `dataDirClaim.test.ts`'s reason: the same body inside a table that did *not* ask must come back with no `md:` rule at all, or what is being pinned is a context that leaks rather than one that carries.
The other four renderings are `UsagePeriods.test.tsx`, `ui/Disclosure.test.tsx`, `ui/LimitField.test.tsx` and `ui/ListView.test.tsx`, and they are on the same argument again.
`UsagePeriods` prints a percentage against a ceiling Anthropic does not publish: a day and a month are measured against the weekly one spread over their own length, which is a **pace** — 254% of a pro-rated $314 on the transcripts it was written against — so what is pinned is that the sentence saying where the number came from cannot be wired apart from the number, and it fails in both directions, since the same sentence over a weekly view implies that window is unguarded.
`Disclosure` exists because a hit target is invisible from every file that has one, and its ARIA fails the other way: a `role` or an `aria-expanded` on a native `<details>` is redundant in one engine and wrong in another, and the reader who finds out is using a screen reader rather than editing this file.
`LimitField` is the one control in the kit that can express "no limit at all", and a picker whose two options are the wrong way round throws nothing, typechecks, looks right on the page and starts an uncapped unattended run.
`ListView` is three boxes that look like one box with two typos in it: the capped one must release both halves of its cap below the breakpoint, where a 320px scroller inside a scrolling pane is a trap with no way past a list but through it, and the plain one must not become a scroll container, which would pin the runs list's sticky header to a box that never scrolls — every difference between the three is invisible on a desktop.
Thirty-three are neither a function nor a rendering, and each earns it its own way: the twenty below, `deployment.test.ts` and `backupRestore.test.ts` after them, and the eleven newer ones at the end of this file.
The count is the length of those three lists and nothing more principled — `settings.test.ts`, `chat.test.ts` and `orchestrator.test.ts` open a database too and are on the function list, because what they pin is a value and the database is only what `config.ts` binds at import.
`src/app/api/chat/[id]/route.test.ts`, `chatOrder.test.ts`, `chatTurn.test.ts`, `haltedMembers.test.ts`, `mergeQueueOrder.test.ts`, `mergeQueueView.test.ts`, `bootBlocks.test.ts`, `assistBudget.test.ts`, `cycleDeadline.test.ts`, `slotProbes.test.ts`, `snapshotCoalesce.test.ts`, `fleet.test.ts`, `src/app/api/agents/route.test.ts`, `src/app/api/health/route.test.ts`, `src/app/api/status/route.test.ts`, `runOrigin.test.ts`, `requestLog.test.ts`, `dataDirClaim.test.ts`, `shutdown.test.ts` and `instanceReading.test.ts` are the twenty that open the database, and what they pin is different in kind.
The first names a throwaway `DATA_DIR` and calls the handler, because what it pins is a *payload key*: the chat page polls that one route, so a list left out of its answer is frozen on screen until a reload, which is exactly what it did for as long as a comment claimed otherwise.
The second is in the SQL itself: a thread ordered by a random UUID puts a denial note above the reply it is a footnote to, which reverses what the operator is being told.
The third drives `sendChatMessage` through a failed pre-spawn setup, because what it pins is a *state transition* rather than a return value (a chat thread stranded at `thinking` for ever by one failed `writeFileSync`, unusable until the server restarts).
The fourth halts a real instance through `stopInstance` and then asks `reopenRun` and `reviveBlockedDependents` about its members, and drives the same pick-up against a graph's deferred nodes to pin `reviveBlockedBlocks` — the two halves of one question, because what it pins is a *join*: a halted member is an ordinary `blocked` row with a null `work_dir`, indistinguishable from the one the revive exists to rescue except by `workflow_instance_runs`, so every way of getting this wrong typechecks, throws nothing and reads identically on the page — the only evidence is a billed agent working under a workflow the page says is stopped.
Its three control cases are half the test, and the half more easily broken: a chain outside any workflow, and one inside an instance still `started`, must still wake exactly as before.
The fifth is in the SQL as well, `chatOrder.test.ts`'s grounds one table over: `nextQueuedIn`'s ORDER BY is the whole of what decides which branch is merged next, and reading the per-batch `position` first sorted a batch queued while the worker was still draining an earlier one into the middle of it.
It also pins the repository term beside it — that a branch in one repository stays eligible while another repository's is in flight, and that within one repository nothing does — because those are one question and the way to get the first is to drop the second.
Nothing crashes — every item is still re-previewed against git at its own turn — so all that is lost is the operator's sequence, in merge commits in a directory they own, with nothing afterwards to say that was not the order they chose.

The broken-link cases are there because the tempting implementation drops what it cannot resolve, which turns "this vault has 212 dangling links" into a graph that reads as complete, and the complete-looking one is the reading an operator would act on.

`forceLayout.test.ts` is the arithmetic under it, and four of its cases are for faults that produce a picture rather than an error.

`fileCostNotice.test.ts` pins the two ways that feature is worse than not shipping it, and neither shows up in a typecheck, a smoke test or a run's log. **Drift is the expensive one**: the text joins the cached prefix, so a generator carrying an order-dependence or a clock would cold-start every token behind it on the next cycle of the same run — the run still works, it just costs several dollars a cycle more, for a notice worth a few cents — and freezing the column is only worth anything if what it freezes is deterministic. **Bloat is the quiet one**, since every character is re-read on every turn of every cycle, so a repository with very long paths has to cost a shorter list rather than a bigger prompt and a notice over its budget looks exactly like one under it.
